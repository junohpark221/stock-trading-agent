# 트레이딩 도메인 PR 리뷰

## 사용법
```
/review-pr [PR번호 또는 브랜치명]
```

인자가 없으면 현재 브랜치의 변경사항을 리뷰합니다.

## 리뷰 프로세스

### 1. 변경사항 수집
- PR 번호가 주어진 경우: `gh pr diff <PR번호>`
- 브랜치가 주어진 경우: `git diff main...<브랜치명>`
- 인자 없는 경우: `git diff main...HEAD`

### 2. 코드 품질 리뷰
- Python PEP 8 스타일 준수
- 타입 힌트 사용 여부
- 에러 핸들링 적절성
- 테스트 코드 포함 여부
- 코드 복잡도 (함수 길이, 중첩 깊이)

### 3. 보안 리뷰
- API 키/시크릿 하드코딩 여부
- SQL injection 가능성
- 입력값 검증
- 로그에 민감 정보 노출 여부
- `.env` 파일이 커밋에 포함되지 않았는지 확인

### 4. 트레이딩 로직 리뷰
- 주문 수량/금액 검증 로직
- 소수점 처리 (Decimal vs float)
- 동시 주문 처리 안전성
- 손절/익절 로직 정확성
- 시장 운영 시간 검증
- 수수료/세금 계산 정확성

### 5. 성능 리뷰
- N+1 쿼리 문제
- 불필요한 API 호출
- 메모리 사용 패턴
- 비동기 처리 적절성

## 출력 형식

```
## PR 리뷰 결과

### 요약
- **PR**: #123 - PR 제목
- **변경 파일**: N개
- **판정**: [승인/수정요청/논의필요]

### 코드 품질
- ...

### 보안
- ...

### 트레이딩 로직
- ...

### 성능
- ...

### 체크리스트
- [ ] 테스트 포함
- [ ] 타입 힌트 추가
- [ ] 문서 업데이트
- [ ] 마이그레이션 필요 여부 확인
```
